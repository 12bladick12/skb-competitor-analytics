# Мониторинг цен конкурентов

Приложение Streamlit для мониторинга цен. Поддерживает Sensoren (Autonics, Balluff, Pepperl+Fuchs, ifm, LANBAO, SICK), BESKONTA, МЕГА-К, ТЕКО и СЕНСОР (`sensor-com.ru`).

**Выбранный вариант размещения: Streamlit Community Cloud + Supabase PostgreSQL, публичный доступ без входа.** Пошаговый запуск: [docs/STREAMLIT_CLOUD.md](docs/STREAMLIT_CLOUD.md). В Community Cloud выбирайте `streamlit_app.py`: он запускает сборщик автоматически и сохраняет историю во внешней базе. Docker для этого варианта не нужен.

Ниже также сохранена инструкция локального запуска с SQLite. Она нужна для разработки; в облачном режиме параметры PostgreSQL обязательны. Общая история и управление заданиями доступны любому посетителю.

**Sensoren:** из Community Cloud подтверждён HTTP 403 на robots.txt. Для запуска обычной кнопкой подключите внешний сборщик через `start_sensoren_agent.cmd` на компьютере с доступом к сайту. Он получает задания из Supabase и сохраняет результаты в тот же запуск. Компьютер и процесс должны оставаться включёнными. [Подключение и размещение на сервере](docs/SENSOREN.md).

## Версия 2: каталоги и сравнение

- «Сбор цен»: все конкуренты или выбранные галочками производители, полный обход публичных карт и разделов, постоянная очередь с продолжением.
- «База товаров»: поиск, характеристики каждого исполнения, выбор позиций для сравнения.
- «Сравнение цен»: компактный график на артикул, изменение за период, наша текущая цена и разница в одной валюте.
- «Запуски»: прогресс по сайтам, ошибки страниц, продолжение прерванного обхода.
- История модели открывается по ссылке из базы или сравнения.

Шаблон наших цен: [examples/comparison_template.xlsx](examples/comparison_template.xlsx), также скачивается в интерфейсе. Сопоставление задаётся явно, автоматического подбора аналогов нет. [Форматы, расчёты и ограничения](docs/CATALOGS.md).

Схема базы расширяется автоматически без удаления прежней истории. При обновлении версии перезапустите приложение и внешний сборщик Sensoren; протокол 2 поддерживает каталог. Старые результаты сохраняются, характеристики для них появятся после нового сбора карточек.

## Быстрый запуск на Windows

Из каталога `price_monitor_app`:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.\run.ps1
```

Открыть http://localhost:8501. Скрипт запускает интерфейс и скрытый процесс сборщика. Закрытие **вкладки браузера** не останавливает сбор. Закрытие самого процесса Streamlit в этом скрипте останавливает оба процесса; при следующем старте задания возобновятся после истечения блокировки (до 120 секунд). Для постоянного сервера используйте Compose либо два независимых сервиса.

Можно запустить отдельно в двух терминалах (из одной рабочей папки):

```powershell
python -m price_monitor.worker
python -m streamlit run app.py --server.address=127.0.0.1
```

Требуется Python 3.11–3.13. Для обоих процессов используется один абсолютный путь `PRICE_MONITOR_DB`; по умолчанию `data/prices.sqlite3` относительно рабочей папки.

## Внутренний сервер

```sh
docker compose up --build -d
docker compose logs -f worker
```

Альтернативный способ размещения, если понадобится собственный сервер: два контейнера используют один локальный Docker volume, база, WAL и SHM находятся вместе. Порт опубликован на `127.0.0.1:8501`. Для публичного адреса нужен reverse proxy с TLS и WebSocket; авторизация приложению не требуется. Посетители видят общую историю и могут остановить общий запуск.

Исходящий доступ сборщика: HTTPS/443 к пяти доменам из `price_monitor/sources.py` и их `www`-алиасам, DNS. SQLite нельзя размещать на SMB/NFS. Оставьте одну реплику сборщика: SQLite lease также предотвращает случайный запуск второй. При вынужденном завершении старого процесса новый сборщик ждёт освобождения lease до 120 секунд. Для обслуживания остановите сервисы, сохраните резервную копию и обновите образ; файл БД сохраняется в volume.

## Работа с заданиями

Для Sensoren подтверждён HTTP 403 из Community Cloud и успешное чтение шести брендов с компьютера владельца. **`start_sensoren_agent.cmd`** подключает сборщик к заданиям кнопки Streamlit. **`run_sensoren.cmd`** оставлен для отдельного ручного сбора. [Порядок запуска и диагностика Sensoren](docs/SENSOREN.md).

Скачайте шаблон в интерфейсе или используйте `examples/tasks.csv`. Пример содержит 11 заданий: все шесть иностранных брендов и четыре российских источника, включая одну снятую с производства модель СЕНСОР. Это реальные ссылки аудита; цены могут меняться.

| Столбец | Содержание |
|---|---|
| source | `sensoren`, `beskonta`, `megak`, `teko`, `sensor`; также принимается домен или название источника |
| manufacturer | Один из производителей, относящихся к источнику |
| article | Точная модель или маркировка исполнения, обязательно текст |
| product_url | Полная HTTPS-ссылка на карточку товара |
| url_template | Альтернатива ссылке, например `https://mega-k.com/products/{article}` |

Для каждой строки заполните ровно один из двух последних столбцов. `{article}` кодируется как часть URL; транслитерация, изменение регистра и автоматический поиск не выполняются. У большинства сайтов адрес не выводится из артикула — используйте точные ссылки. Шаблоны поиска исключены: аудит выявил запреты поиска в robots.txt. Доступные карты сайтов перечислены в отчёте; автоматическое сканирование всего каталога не включено.

CSV поддерживает UTF-8/BOM и Windows-1251, разделители `;`, `,`, табуляцию. XLSX читает лист «Задания» или первый лист. Лимиты: 10 МБ, 10 000 заданий, без формул и макросов. Есть русские алиасы заголовков «Источник», «Производитель», «Артикул», «Ссылка», «Шаблон». Если есть ошибка, весь запуск блокируется до её исправления. Повторная загрузка после завершения создаёт новый снимок; активный запуск во всей системе только один.

Артикул проверяется по заголовку/маркировке самой карточки. Похожий артикул, цена аналога, сумма корзины, стоимость доставки и цена в блоке рекомендаций не используются. Для BESKONTA с вариантами требуется совпадение с маркировкой выбранного в HTML исполнения; другие варианты отмечаются «Уточните исполнение». Например, для страницы BORE01 подтверждено `BORE01-S2000-8-20-P01`.

## Статусы и история

«Цена получена», «Цена по запросу», «Цена не опубликована», «Товар не найден», ошибки доступа и ошибки структуры хранятся отдельно. Отсутствующая цена — NULL, а не ноль. Числа хранятся десятичными строками, без ошибок float; валюта не пересчитывается. Наличие имеет отдельный статус. Значения по умолчанию и предыдущая цена не подставляются при ошибке.

История относится к сочетанию источник + производитель + артикул + раскрытый URL. Изменение ссылки создаёт новое правило, старое остаётся в истории. Время сохраняется в UTC. Экспорт включает статусы, исходный текст цены, HTTP-код и SHA-256 HTML-ответа; XLSX/CSV защищены от выполнения формул в текстовых значениях. Это каталог публичных предложений, без сопоставления с собственной номенклатурой.

## Устройство

`Streamlit → очередь runs/jobs в SQLite → worker → адаптер источника → observations в SQLite → таблицы/история/экспорт`.

Пять потоков максимум, один на сайт. Интервал между запросами одного сайта минимум 2 секунды, увеличивается по Crawl-delay. Проверка robots.txt в каждом запуске; wildcard и приоритет самого длинного правила поддержаны. 401/403/429 и страницы CAPTCHA останавливают источник до нового ручного запуска. При 429 записывается Retry-After, повторов нет. Сетевые ошибки и временные 5xx имеют один повтор; три ошибки подряд останавливают источник. Ошибка robots.txt тоже останавливает источник. Разрешены только настроенные домены; URL и каждый redirect проверяются. DNS на частные адреса отклоняется.

Запись результата и завершение задания атомарны. Ограничение UNIQUE(job_id) исключает двойную запись при восстановлении. Heartbeat обновляется раз в 10 секунд; lease истекает через 120. Прерванное задание повторяется, записанное остаётся завершённым. Остановка источника сохраняется и переживает рестарт. Остановка пользователем помечает оставшиеся задания отменёнными, полученные данные остаются. Интерфейс обновляет прогресс раз в 10 секунд.

## Проверка и эксплуатация

```sh
python -m unittest discover -s tests -v
python -m price_monitor.cli import examples/tasks.csv
python -m price_monitor.worker --once
python -m price_monitor.cli export 1 data/run_1.xlsx
python -m price_monitor.cli backup data/backups/prices.sqlite3
```

Последние три команды выполняйте с реальным номером запуска; `import` и `worker` запускают реальный сбор. Офлайн-тесты используют сохранённые фрагменты карточек, поддельный HTTP-клиент и временную БД. SQLite backup API делает согласованную копию при работающем WAL; не копируйте только основной файл живой базы. Восстановление: остановить оба процесса и заменить БД резервной копией в новом пустом каталоге данных. Старую БД и связанные WAL/SHM сохраните отдельно. Данные автоматически не удаляются.

Аудит: [docs/AUDIT.md](docs/AUDIT.md), машиночитаемые результаты — `docs/audit/http_audit*.json`. Итог проверки: [docs/VALIDATION.md](docs/VALIDATION.md). Повторный ограниченный аудит запускается явно: `python tools/audit_sources.py`. HTML-ответы сохраняются в исключённую из Git папку `docs/audit/raw`; их SHA-256 есть в журнале. Производственный сбор полные HTML не хранит.
