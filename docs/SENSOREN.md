# Как собирать цены Sensoren

## Что установлено 28 сентября 2026

В первом запуске Streamlit Community Cloud задание SI5000 получило **HTTP 403**. Сборщик остановил ещё пять заданий этого источника. Сообщение «требует авторизацию или ограничил доступ» было общим: оно не доказывает, что для просмотра товара действительно нужен логин.

С компьютера владельца тот же клиент с тем же User-Agent `PriceMonitor/1.0` получил `robots.txt` и все шесть карточек с HTTP 200. Проверенные карточки разрешены robots.txt. Цены читаются из основного блока HTML: `.product-info .product-info__all-order-price .price`. Артикул и производитель сверяются с заголовком самой карточки. JavaScript для получения этих шести цен не требуется.

| Производитель | Модель | Цена при проверке, ₽ |
|---|---|---:|
| ifm | SI5000 | 29 530 |
| Autonics | THD-R-T | 11 140 |
| Balluff | BSP B600-EV003-A02A0B-S4 | 41 950 |
| Pepperl+Fuchs | RaDec-D | 36 800 |
| LANBAO | DPG-10TN | 6 660 |
| SICK | FTS-I100F14A | 63 160 |

Это снимок опубликованных цен, а не гарантия их неизменности. Пример первоисточника: [карточка SI5000](https://sensoren.ru/product/datchik_potoka_ifm_electronic_si5000/).

Различие между облаком и локальной сетью подтверждено. Точная причина HTTP 403 не установлена: для неё нужны сведения владельца сайта или его ответ с описанием ограничения. Исходный облачный запуск не сохранил тело отказа и не позволяет различить отказ на robots.txt и карточке. В новой версии ошибки содержат этап, URL и HTTP-код.

## Повторный сбор с компьютера владельца

1. На компьютере должна быть папка приложения, установлен Python 3.11–3.13 и зависимости из `requirements.txt`.
2. Реквизиты Supabase должны находиться в локальном `.streamlit/secrets.toml`. Этот файл не входит в GitHub или ZIP исходников.
3. Дважды нажмите **`run_sensoren.cmd`**. Он использует ранее сохранённые в Supabase задания Sensoren. Окно показывает ход сбора; дождитесь сообщения с номером запуска.
4. В Streamlit откройте **«Результаты» → «Обновить результаты»** и выберите этот номер. Для запуска будет указано «Sensoren: локальный сбор HTTP».

Если нужно собрать другой список моделей, откройте терминал в папке приложения:

```powershell
python -m price_monitor.sensoren_local --file "мои_задания.xlsx"
```

Формат заданий тот же, что в веб-приложении: `source`, `manufacturer`, `article`, `product_url` или `url_template`. Из корректной таблицы выбираются строки Sensoren. Обычная кнопка «Запустить сбор» на сайте по-прежнему выполняет запросы из облака; локальный запуск включается отдельно на компьютере.

## Хранение и ошибки

Перед отправкой в базу программа сохраняет JSON-снимок и XLSX/CSV в `data/sensoren_runs/`. При обрыве подключения локальные файлы остаются. Повторная отправка выполняется командой, которую напечатает программа:

```powershell
python -m price_monitor.sensoren_local --resume "data/sensoren_runs/ID-СНИМКА.json"
```

Один и тот же снимок повторно возвращает тот же номер запуска. Запись в Supabase атомарна. Старые результаты, в том числе облачный HTTP 403, остаются в истории. Локальный запуск сразу сохраняется завершённым и не попадает в очередь облачного сборщика.

Запросы к Sensoren идут последовательно с паузой не менее двух секунд и проверкой robots.txt. CAPTCHA, HTTP 401/403/429 и запреты robots.txt останавливают сбор. Если обычный доступ из локальной сети также перестанет работать, необходимы API, фид или согласованный доступ владельца сайта.

## Для работы полностью из облака

Нужно согласовать с Sensoren доступ с адреса сборщика либо получать прайс через предоставленный ими API/фид. Публичный ценовой API или фид в выполненном аудите не обнаружен. Другой вариант размещения сборщика требует проверки доступности и допустимости доступа с выбранного сервера. Локальный режим не исправляет HTTP 403 из инфраструктуры Community Cloud и не обещает доступ с любого адреса.
