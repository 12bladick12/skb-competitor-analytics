# Судебный мониторинг: реализация и запуск

Основа: production commit `06e8d00be6d5203ab4405d0746009cb2af4c2c3c`.
Повторная проверка доступа и рабочая форма ФНС: [COURT_ACCESS_AUDIT.md](COURT_ACCESS_AUDIT.md).
Раздел находится внутри «Новостей». Текущий выпуск — внутренний пилот,
публичная проекция выключена. Рабочая база и приложение этим пакетом не изменены.

## Что работает в коде

- Реестр пяти исходных юридических лиц с ИНН/ОГРН, проверкой контрольных цифр и ссылками
  на официальные реквизиты. Реестр расширяется записями `court_entity`; первичный список
  используется только при пустой базе. ФНС, исторические названия и другие юрлица ещё
  не объявлены проверенными.
- Очередь `court_collect`, отдельный процесс Actions, общее атомарное создание заданий
  новостей и судов, дедупликация судебного задания независимо от отчётного месяца.
  Обычный worker не берёт судебные задания. Просроченный процесс не может записать результат.
- Отдельные записи дел, сторон, документов, событий, производств, кандидатов, проверок,
  предыдущих версий и позиций обхода в Neon; доказательства — в существующем закрытом Drive.
  Файл записывается прежде, чем фиксируются данные и позиция продолжения.
- СудАкт: обычная браузерная форма, запросы по ИНН и именам, переходы по страницам,
  загрузка актов, проверка ИНН в структурированном списке сторон. Неподтверждённые
  совпадения остаются кандидатами. Полный обход копий не сертифицирует полноту суда.
- Сохранение старых данных при сбоях, чередование компаний/источников и продолжение
  с сохранённой позиции. Повторная проверка известных доступных копий ежедневно,
  включая явно закрытые дела по воскресеньям.
- Архив с фильтрами и пагинацией, карточки, источники, даты проверок, разные денежные
  показатели. Закрытый пилот видит только администратор при `courts.enabled=true`.
- После сертификации: судебные события в ленте, сводке, черновиках и Word/PDF/ZIP.
  Исторические события относятся к исходной дате. Исходные новости и сохранённые отчёты
  не перезаписываются судебным сборщиком.

## Что ещё не является рабочим полным сбором

КАД, Банк решений, ФССП, ВС, КС, Федресурс, ФНС и каталог ГАС включены в проверку
доступности. Для КАД/ФССП/ВС выполняется попытка обычного поиска. Это **диагностика**,
а не законченные адаптеры всех карточек и документов. Результат каталога судов не
означает обход сайтов районных судов и мировых судей. Полная региональная матрица,
нормализация первичных карточек, связанные инстанции и массовые вложения ещё требуют
проверенных ответов источников либо согласованного API. Автоматическое OCR не включено.

16.10.2026 проверка новой реализации в локальном Edge: КАД и ФССП — тайм-аут поиска;
ВС — ошибка доступа браузера; СудАкт — получена выдача и документ, участие в нём
осталось кандидатом. На сохранённых актах парсер правильно определил ТЕКО в
А76-27310/2021 и СОЧЕР в А76-37743/2022 как истцов. Эти результаты не подтверждают
работоспособность из GitHub Actions. Диагностика хранится локально в `data/`, в Git не попадает.

Ключи пробного доступа Контур.Фокуса и Pravo Data отсутствуют. Их реальные ответы,
пагинация, полнота и цена пока не сравнены. Платные запросы и покупка не выполнялись.
Публичный запуск до завершения этих работ невозможен по встроенным условиям выпуска.

## Подготовка частного сборщика

1. Развернуть код из проверенного коммита. Секреты хранить в Streamlit Secrets / GitHub
   Secrets. Не переносить каталог `data/`, локальные `.streamlit/secrets*.toml` и тестовые
   базы в репозиторий. В имеющемся подключении доступны операции кода GitHub;
   создание нового репозитория, установка Actions Secrets и управление биллингом
   этим подключением не предоставлены.
2. Создать **закрытый** репозиторий `skb-competitor-analytics-ops`. Скопировать
   `operations/courts.yml` в `.github/workflows/courts.yml`. Рабочий репозиторий приложения
   остаётся публичным. Workflow запускается в 04:17, 10:17 и 16:17 UTC
   (09:17, 15:17 и 21:17 Екатеринбурга). После полного успешного дневного сбора
   повторный сбор не ставится. Ручное задание использует ту же очередь.
3. Проверить остаток бесплатной квоты владельца, включить остановку платного превышения
   и только затем установить `COURT_FREE_BUDGET_VERIFIED=true` и
   `COURT_WORKER_ENABLED=true`. Лимит одного workflow — 18 минут, полезной работы —
   600 секунд. При трёх запусках ежедневно верхняя граница workflow за 31 день —
   1674 минуты, без других репозиториев и ручных запусков. Это не проверка фактической
   квоты аккаунта и не обещание бесплатности при дополнительной нагрузке.
4. Указать `COURT_CODE_SHA` — полный SHA коммита приложения. Секрет `SKB_COURT_CONFIG`
   содержит JSON с разделами `cloud` и `drive` из действующей конфигурации. Не печатать
   этот JSON и не сохранять его в файлы проекта. Права Google Drive нужны только
   существующему закрытому хранилищу. Настройки `auth`, `access` и базы цен не нужны.
5. Один раз выполнить `python -m courts.runner --migrate` с тем же секретом в окружении.
   Миграция повторяемая, добавляет вид задания и функцию claim; не очищает таблицы.
   Загрузка страниц приложения миграции не выполняет.
6. Для кнопки приложения заполнить секцию `[courts]` из шаблона: `enabled=true`, имя
   служебного репозитория и отдельный fine-grained token с `Actions: write` только
   для него. Успешная постановка в Neon не зависит от успеха dispatch. При сбое
   dispatch интерфейс сообщает, что задание сохранено и ожидает расписания.
7. Выполнить первый workflow вручную; сравнить его `court_check` с локальной диагностикой.
   Установить работоспособные адаптеры первичных источников/API, провести полную
   загрузку и сверку по `courts/control_cases.json` и расширенной выборке всех юрисдикций.
   Затем начать 14-дневную пробную эксплуатацию. Частичные дни не засчитываются.

## Условия открытия

`python -m courts.runner --check-release` читает состояние и выводит причины отказа.
Проверяются все подтверждённые юрлица и категории арбитраж/общая юрисдикция/мировые
судьи/ВС/КС/ФССП/банкротство, ФНС и история юрлиц, контрольные дела и доказательства,
14 предыдущих последовательных дней полного автоматического сбора из Actions.
Дневной сбор обязан закончиться в те же местные сутки. Историческая полнота и
обновление известных дел должны быть подтверждены самим адаптером.

`python -m courts.runner --activate` повторяет проверки и только при успехе создаёт
запись допуска `court_release/public`. Флаг `courts.enabled` сам по себе читателям
раздел не открывает. Не следует вручную создавать запись допуска в базе.

При последующих сбоях данные сохраняются. После 36 часов без успешной полной проверки
показывается устаревание; свежая неуспешная попытка эту отметку не снимает.

## Контракт адаптера и проверки

Адаптер возвращает `courts.model.Page`: типизированные списки дел, событий, документов,
производств, кандидатов, SHA-256 → bytes, позицию следующей страницы и границы охвата.
Точные ИНН/ОГРН, процессуальная роль и её доказательство обязательны для подтверждения.
`status=success` запрещён до завершения пагинации. Неизвестные суммы/даты — `None`.
Ключ события должен различать несколько актов по одной карточке; для одинаковых
актов разных источников используется общий подтверждённый `canonical_event_id`.
Изменения HTML-обвязки не являются процессуальным событием. Связи инстанций и
производств заполняются только по явному идентификатору из источника.

Тесты: `python -m unittest discover -s tests -p 'test_courts*.py' -v`;
для транзакционных тестов — отдельная localhost-база `skb_test` через
`SKB_TEST_POSTGRES_URL`. Регрессии: `test_cloud_*.py` и `tests_prices`.
Живая проверка без записи в Neon/Drive:
`python scripts/probe_court_sources.py --output data/court-probe --sources kad fssp vsrf sudact_arbitral`.
На Windows можно добавить `--channel msedge`. Страницы с ограничением доступа
сохраняются как диагностика, повторные запросы к этому хосту в запуске прекращаются.
