# Публикация в Streamlit Community Cloud без авторизации

Выбранная схема: **GitHub → Streamlit Community Cloud → Supabase PostgreSQL**. Посетитель открывает ссылку `https://имя.streamlit.app` и сразу работает с приложением. Аккаунты GitHub, Streamlit и Supabase нужны только владельцу для размещения и настройки.

Готовый код содержит облачную точку входа `streamlit_app.py`, запуск одного фонового сборщика на процесс и PostgreSQL-хранилище. История, задания и результаты общие для всех. Любой посетитель может загрузить задания, запустить и остановить сбор, посмотреть и скачать результаты.

## 1. Создайте проект Supabase

Откройте [панель Supabase](https://supabase.com/dashboard), создайте организацию и новый проект, например `price-monitor`. Сохраните пароль базы, который зададите при создании проекта. Тариф выберите в панели по требуемым ресурсам и актуальным условиям; приложение не требует платных функций Supabase Auth или Storage.

После готовности проекта нажмите **Connect** и выберите **Session pooler**. Скопируйте показанные `host`, `user`, `port` и название базы. Обычно порт — `5432`, база — `postgres`, имя пользователя имеет вид `postgres.<идентификатор-проекта>`. Хост берите из панели своего проекта: он не вычисляется по названию региона. Session pooler поддерживает IPv4. [Подключение к PostgreSQL](https://supabase.com/docs/guides/database/connecting-to-postgres).

Таблицы создавать вручную не нужно. При первом подключении приложение создаёт схему `price_monitor`, таблицы истории и очередь. Схема не добавляется в публичный Data API. Подключение использует пароль PostgreSQL; API-ключи Supabase и настройка пользовательской авторизации для приложения не нужны.

### Если проект Supabase уже создан

1. Откройте проект в [Supabase Dashboard](https://supabase.com/dashboard). Адрес вида `https://PROJECT-REF.supabase.co` — API-адрес проекта. Управление находится по адресу `https://supabase.com/dashboard/project/PROJECT-REF`.
2. Дождитесь готовности базы. Если проект приостановлен, возобновите его в панели.
3. Нажмите **Connect** вверху страницы. В способе подключения выберите **Session pooler**. Если есть выбор формата, оставьте **URI**.
4. В строке соединения найдите поля по примеру ниже. Не вводите эту строку целиком в поле `host`.

```text
postgresql://postgres.PROJECT-REF:[YOUR-PASSWORD]@POOLER-HOST:5432/postgres
             └────── user ─────┘                 └─ host ─┘ port └dbname┘
```

| Поле в Streamlit Secrets | Что взять из Supabase |
|---|---|
| `host` | Текст между `@` и `:5432`, без `https://`, без порта и без завершающего `/` |
| `port` | `5432` для выбранного Session pooler, числом без кавычек |
| `dbname` | `postgres`, если это имя показано в Connect |
| `user` | Полностью `postgres.PROJECT-REF`, включая точку и идентификатор проекта |
| `password` | Пароль базы, заданный при создании проекта |
| `sslmode` | `require` |

`PROJECT-REF` — часть API-адреса перед `.supabase.co`. Точное имя `POOLER-HOST` берите из Connect: по одному API-адресу его определить нельзя. Оставьте остальные настройки базы по умолчанию. [Режимы подключения и реквизиты](https://supabase.com/docs/guides/database/connecting-to-postgres).

Пароль базы вводится только в **Secrets приложения Streamlit**. В строке Supabase вместо него может оставаться `[YOUR-PASSWORD]`: эту заглушку необходимо заменить своим паролем. Пароль входа в аккаунт Supabase и ключи `anon`, `publishable` или `service_role` для этого поля не подходят.

Если пароль базы не сохранён, откройте **Database → Settings**, задайте новый пароль и сохраните его в менеджере паролей. При смене пароля обновите его и в других приложениях, которые уже подключены к этой базе. [Сброс пароля базы](https://supabase.com/docs/guides/troubleshooting/how-do-i-reset-my-supabase-database-password-oTs5sB).

Для работы текущего приложения не нужно вручную создавать таблицы, импортировать CSV в Table Editor, добавлять пользователей в Authentication или настраивать Storage. CSV/XLSX с заданиями загружается через интерфейс Streamlit после публикации. Вход владельца в панель Supabase остаётся необходимым для администрирования; посетители приложения работают без аккаунтов.

## 2. Создайте репозиторий GitHub

**Для текущего проекта:** исходники публикуются в `12bladick12/skb-competitor-analytics`, в отдельной ветке `price-monitor`. При создании приложения выбирайте эту ветку. Следующие рекомендации о новом репозитории нужны только для переноса исходников в собственную отдельную копию.

Создайте отдельный репозиторий, например `price-monitor-streamlit`. Можно использовать приватный репозиторий и отдельно сделать само приложение публичным.

Загрузите **содержимое папки приложения** в корень репозитория. Для удобства подготовлен архив `dist/price-monitor-streamlit.zip`: распакуйте его на компьютере и загрузите распакованные файлы, сохранив папки. Сам ZIP загружать вместо исходников не нужно.

В корне должны лежать:

```text
streamlit_app.py
app.py
requirements.txt
README.md
.gitignore
.streamlit/
  config.toml
  secrets.example.toml
price_monitor/
examples/
docs/
```

Папка `.streamlit` может быть скрыта файловым менеджером. При загрузке через браузер проверьте, что `.streamlit/config.toml` действительно появился в GitHub. Если его нет, создайте файл с таким именем через **Add file → Create new file** и скопируйте локальный конфиг.

Архив содержит только приложение и документацию. Локальные базы, временные файлы, реальные Secrets и исходные Excel/RAR из родительской рабочей папки в него не входят.

## 3. Создайте приложение Streamlit

Войдите в [Streamlit Community Cloud](https://share.streamlit.io/), подключите GitHub и выберите **Create app**. Для текущего проекта укажите репозиторий `12bladick12/skb-competitor-analytics`, ветку `price-monitor` и **Main file path: `streamlit_app.py`**. Если вы перенесли приложение в новый репозиторий, выберите его фактическую ветку, обычно `main`. Выберите свободное имя адреса приложения. [Порядок публикации](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy).

В **Advanced settings** установите **Python 3.13**. Пакеты будут установлены автоматически из `requirements.txt`.

## 4. Добавьте Secrets

В поле **Secrets** в Advanced settings вставьте этот шаблон с настоящими значениями из Supabase:

```toml
[database]
host = "ВАШ-ХОСТ-ИЗ-SESSION-POOLER"
port = 5432
dbname = "postgres"
user = "postgres.ВАШ-ИДЕНТИФИКАТОР-ПРОЕКТА"
password = "ВАШ-ПАРОЛЬ-БАЗЫ"
sslmode = "require"
```

Вводите пароль как TOML-строку. Если в пароле есть `"` или обратная косая черта, экранируйте их согласно TOML либо используйте одинарные кавычки, если в пароле нет одинарной кавычки. Процентное кодирование не требуется: параметры передаются отдельно, без сборки URL.

В репозиторий добавляйте только `secrets.example.toml` с заглушками; реальные значения вводятся в панели Streamlit. Это серверное подключение к хранилищу, посетители не вводят пароль и не видят его. При неверных параметрах приложение выводит сообщение о недоступном хранилище и не переключается на временную SQLite-базу.

Если приложение уже создано, откройте его **Settings → Secrets**, вставьте весь блок `[database]` и сохраните. При первом развёртывании используйте **Advanced settings → Secrets**. Не добавляйте ограждения Markdown (строки с тройными обратными кавычками) в поле Secrets. [Управление Secrets](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management).

## 5. Нажмите Deploy

После установки зависимостей появится интерфейс. Сборщик запускается автоматически; отдельный терминал, Docker или сервер не нужны. В Supabase таблицы можно увидеть, выбрав схему `price_monitor`.

До первого успешного запуска Streamlit схема `price_monitor` может отсутствовать — это нормально. После запуска откройте **Table Editor** и выберите эту схему вместо `public`. В ней появятся:

| Таблица | Содержимое |
|---|---|
| `rules` | Сохранённые модели и ссылки |
| `runs` | Запуски сбора |
| `jobs` | Очередь заданий каждого запуска |
| `observations` | Полученные цены, наличие и ошибки |
| `source_pauses` | Ограничения источников в ходе запуска |
| `worker_lease` | Блокировка единственного активного сборщика |
| `schema_version` | Версия структуры базы |

Таблицы с моделями и результатами будут пустыми до первого сбора. Вносить записи в них вручную не требуется. При желании наличие таблиц можно проверить через **SQL Editor → New query**:

```sql
select table_name
from information_schema.tables
where table_schema = 'price_monitor'
order by table_name;
```

Запрос только показывает список таблиц. Ожидаются семь строк после успешного подключения приложения. Не добавляйте схему `price_monitor` в Exposed schemas: текущий код обращается к PostgreSQL напрямую с сервера Streamlit.

Если появилось сообщение о хранилище, проверьте Secrets: выбран именно Session pooler, хост и имя пользователя целиком скопированы из Connect, указан пароль базы, проект Supabase работает. После исправления Secrets перезагрузите приложение в панели Streamlit.

## 6. Включите публичный доступ

Откройте **Settings → Sharing → Who can view this app** и выберите **This app is public and searchable**. Для приложения из приватного GitHub-репозитория этот шаг обязателен. [Настройки публичного доступа](https://docs.streamlit.io/deploy/streamlit-community-cloud/share-your-app).

Проверьте ссылку в приватном окне браузера без входа в Streamlit. Должен открыться интерфейс с разделами «Сбор цен», «Результаты», «История модели», «Источники».

## 7. Проверьте первый сбор

На странице «Сбор цен» скачайте примеры, загрузите `tasks_examples.csv` и нажмите «Запустить сбор». Пример содержит 11 моделей. Посмотрите прогресс, затем таблицу результатов и выгрузите XLSX.

Откройте приложение во втором браузере: тот же запуск и история должны быть видны. Перезапустите приложение через панель Streamlit: результаты должны остаться в Supabase. При перезапуске во время сбора незавершённые задания возобновятся после освобождения блокировки, до 120 секунд.

Доступность сайтов проверялась из локальной среды разработки. После публикации нужно подтвердить доступ из инфраструктуры Community Cloud: источники могут по-разному отвечать разным адресам. При блокировке приложение покажет статус и сохранит уже полученные результаты.

## 8. Ежедневная работа

Работа выполняется по публичной ссылке без регистрации. Доступен один общий активный запуск, чтобы посетители не запускали несколько независимых сборов одновременно. Ваша собственная номенклатура не загружается автоматически.

История хранится в PostgreSQL. Локальное хранилище Community Cloud не гарантирует сохранность файлов, поэтому SQLite используется только в локальном режиме. [Ограничение хранения](https://docs.streamlit.io/develop/concepts/connections/connecting-to-data).

Community Cloud переводит приложения без посещений в спящий режим через 12 часов. Во время сна или перезапуска сборщик не работает; после пробуждения он восстанавливает очередь. Для этого ручного режима важно открывать приложение перед запуском; непрерывную работу 24/7 эта схема не обещает. [Спящий режим](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app).
