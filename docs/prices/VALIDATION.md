# Проверка реализации

Дата: 28.09.2026. Среда: Windows, Python 3.13.14, Streamlit 1.61.1. Исходные пользовательские каталоги и архивы не менялись; приложение находится в отдельной папке `price_monitor_app`.

## Подключение внешнего сборщика Sensoren к кнопке Streamlit

Запуск №3 подтвердил HTTP 403 именно на robots.txt. Добавлены маршрут `external_sources`, отдельная блокировка внешнего сборщика, индикатор подключения, повтор Sensoren из результатов и отмена ожидающих заданий при отключённом сборщике. Прежний ручной импорт №2 не подтверждает работу нового маршрута.

Проверены синтаксис изменённых модулей; SQL-команды claim, heartbeat, record и проверки отмены в настоящей Supabase-базе без права владения заданиями — чужая запись отклонена, данные прежних запусков не изменены. На отдельной SQLite-базе проверены исключение Sensoren из облачной обработки, запрет облачного захвата его задания, отмена при отключённом внешнем сборщике и завершение общего запуска. Новые модульные тесты не добавлялись.

После перезапуска приложения пользователем подтверждены новый облачный сборщик `router1` и подключённый внешний сборщик Sensoren. **Запуск №4 завершён успешно**: 28.09.2026, начало 11:25:50 UTC, завершение 11:26:22 UTC, 32 секунды. В общую очередь помещены 11 сохранённых правил запуска №3. Получены 10 цен; один снятый с производства товар СЕНСОР корректно остался без цены. Все 11 карточек ответили HTTP 200.

Шесть заданий Sensoren выполнил внешний сборщик: SI5000 — 29 530 RUB; THD-R-T — 11 140 RUB; BSP B600-EV003-A02A0B-S4 — 41 950 RUB; RaDec-D — 36 800 RUB; DPG-10TN — 6 660 RUB; FTS-I100F14A — 63 160 RUB. Остальные пять заданий выполнил облачный процесс. Результаты находятся в одном запуске №4 в Supabase; состояние запуска — `completed`. Старые запуски №1–3 сохранены.

Это проверка реального выполнения общей очереди после развёртывания. Контрольные задания добавлены непосредственно в очередь с теми же правилами; браузерный клик по кнопке в этой проверке не автоматизировался. Локальные подтверждения: `data/sensoren_queue_verified.json` и журнал `data/sensoren_agent_stdout.log`. Работа Sensoren требует включённого компьютера и процесса сборщика. Детали: [SENSOREN.md](SENSOREN.md).

## Обновление для Streamlit Community Cloud

Выбранное размещение изменено на публичный Streamlit Community Cloud с Supabase PostgreSQL, без входа для посетителей. Добавлены `streamlit_app.py`, автоматический фоновый сборщик и PostgreSQL-драйвер с пулом соединений. Постоянные данные сохраняются в отдельной схеме `price_monitor`; локальный SQLite в облачном режиме не используется даже при ошибке подключения.

Финальный прогон после адаптации: **35 тестов, все прошли**, 11,138 секунды. Проверены сохранение прежнего локального режима, пакетная запись 205 заданий, повторное использование правил, автоматическое выполнение очереди, ограничение частоты проверок отмены, однократный запуск сервиса между перерисовками Streamlit, публичный интерфейс без логина и отсутствие секрета в сообщении об ошибке. Для PostgreSQL проверены генерация SQL, привязка параметров, настройки SSL/пула, транзакционные блокировки и отдельная схема через подменённый драйвер.

Установлен и импортирован psycopg 3.3.6 с binary/pool. В первоначальном прогоне реальная PostgreSQL-база не подключалась. Эти проверки не заменяют сквозной запуск после публикации. Инструкция владельцу: [STREAMLIT_CLOUD.md](STREAMLIT_CLOUD.md).

### Подключение Supabase 28 сентября 2026

**Дополнение после запуска в Community Cloud:** веб-приложение подключилось к базе и выполнило первый сбор. В запуске №1 подтверждены четыре опубликованные цены российских источников и HTTP 403 у первого запроса Sensoren. Последующая проверка тем же HTTP-клиентом с компьютера владельца получила шесть цен Sensoren; результаты атомарно сохранены отдельным завершённым запуском №2. Повторная отправка того же JSON-снимка вернула №2: в базе остался один запуск с этим идентификатором снимка. Эти проверки выполнены на реальных карточках и Supabase. Диагностика и порядок повторного сбора: [SENSOREN.md](SENSOREN.md).

С предоставленными владельцем реквизитами подтверждена авторизация PostgreSQL через Session pooler. Одной атомарной транзакцией создана схема `price_monitor`; отдельным новым соединением подтверждены семь таблиц (`rules`, `runs`, `jobs`, `observations`, `source_pauses`, `worker_lease`, `schema_version`) и версия схемы `1`.

Из локальной среды длинная серия запросов на одном соединении зависает или завершается `SSL error: unexpected eof while reading`. Повторено на psycopg 3 и psycopg2, в обоих режимах pooler; короткие подключения и создание структуры одним SQL-пакетом прошли. Корневая причина сетевого обрыва не установлена. Оставшиеся транзакции наших диагностических попыток закрыты. Полный запуск Streamlit со сборщиком из Community Cloud ещё не проверен: это обязательный следующий шаг после Deploy. Сам факт создания таблиц не подтверждает работу облачного приложения.

Пароль сохранён только в локальном `.streamlit/secrets.toml`, который исключён из GitHub и архива исходников. В настройках создаваемого Streamlit-приложения владелец переносит содержимое этого файла в Secrets.

## Офлайн-проверки

`python -m unittest discover -s tests -v` — **26 тестов, все прошли**. Последний полный запуск занял 10,922 секунды.

Покрыты импорт CSV/XLSX и сохранение ведущих нулей; ошибочные и дублирующиеся задания; формулы; шаблоны URL; XLSX/CSV-экспорт; реальные фрагменты карточек всех шести брендов Sensoren и четырёх российских производителей; цена по запросу/отсутствие цены; исключение цены аналога; исполнение BESKONTA; несовпадение маркировки и бренда; изменение селектора; robots.txt; 401/403/429; недопустимые redirect; миграция URL ТЕКО; конкурентные запуски; lease, восстановление и идемпотентность; резервное копирование; остановка одного источника; отмена запуска с сохранением полученных результатов.

Streamlit AppTest проверяет все четыре раздела с сохранённым результатом, загрузку примера, кнопку запуска, очередь из 11 заданий и кнопку остановки. Загрузка файла в AppTest подменяет файловый виджет, обработка и кнопки приложения выполняются реально. Полная браузерная визуальная проверка не проводилась.

В ограниченной среде Windows стандартные временные папки Python создавались с недоступными ACL; изолированные БД тестов перенесены внутрь рабочей папки. Финальный AppTest запущен с разрешённым доступом к системной временной папке. Это ограничение среды проверки, а не пользовательского формата данных.

## Живой сбор и запуск сервера

Фактический сборщик запущен с отдельной БД `data/live_verification.sqlite3`. Подтверждены цены 10 разных моделей на всех пяти сайтах; ещё одна модель СЕНСОР корректно распознана как снятая с производства без собственной цены. На ТЕКО отдельно проверены новая и старая ссылки после исправления обработки redirect. Первый неуспешный результат ТЕКО сохранён в истории, последующая успешная проверка не перезаписывала его.

Результаты: `docs/audit/live_collection.json`, локальные выгрузки `data/live_results.xlsx` и `data/live_results.csv`. Эти цены — снимки проверки, не постоянные справочные значения. Новые пользовательские запуски используют отдельную БД `data/prices.sqlite3`.

Streamlit был запущен отдельным процессом на `127.0.0.1:18501`; `/_stcore/health` вернул **HTTP 200, ok**. После проверки временный сервер остановлен.

Docker/Compose-конфигурация подготовлена, но Docker в этой среде отсутствует, поэтому образ не собирался. Развёртывание на внутреннем сервере и подключение корпоративной авторизации требуют доступа к этому серверу; здесь выполнены локальная реализация и проверка.
