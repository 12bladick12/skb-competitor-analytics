# BESKONTA, СЕНСОР и ТЕКО: аудит 30.09.2026

## Причины и исправления

Проверены живые публичные страницы, robots.txt, сохранённая очередь запуска №11,
выгрузка из PostgreSQL и обработка сбоев. Доступ выполняется обычным HTTP-клиентом
с проверкой robots.txt перед каждым переходом и ограничением частоты запросов.

| Источник | Что мешало сбору | Исправление |
|---|---|---|
| BESKONTA | Старый `/sitemap.xml` возвращает 404; `/catalog/all/?p=…` запрещён robots.txt. Дополнительно сервер отдаёт заголовок `location` строчными буквами, а преобразование заголовков в обычный Python dict теряло поиск без учёта регистра: корректные HTTP 301 ошибочно считались пустыми перенаправлениями. | Точка входа `/sitemap-1.xml` из robots.txt; исключена запрещённая пагинация. Сохранён регистронезависимый доступ к HTTP-заголовкам. Исполнения внутри одной карточки сохраняются отдельно. |
| СЕНСОР | Очередь попадала в `/catalog/arhiv-produktsii/`, запрещённый robots.txt. Общий обход включал карты новостей и аналогов. | Начало с `/sitemap/main.xml`, затем `Goods*.xml` и `category.xml`. Архив, страницы с query string и посторонние карты исключены. |
| ТЕКО | Служебные страницы `/filter/…/` запрещены robots.txt. Удалённые карточки перенаправляются на общий каталог. У части собственных товаров пустой видимый блок свойств, но производитель есть в JSON-LD основной карточки. | Отдельные правила навигации; переход карточки на каталог считается пропуском. При отсутствии видимого производителя используется бренд основной JSON-LD Product, имя которой соответствует заголовку. Чужие бренды исключаются. |

Один только заголовок с названием ТЕКО, домен сайта или упоминание в подвале
не подтверждают изготовителя. Рекомендации других товаров в JSON-LD не используются
для подтверждения бренда основной карточки. Видимое поле производителя имеет приоритет.

## Архитектура

- `catalog_strategies.py`: отдельные правила точек входа и допустимых страниц каждого из трёх сайтов.
- `details.py`: извлечение полей и проверка производителя с учётом разметки источника.
- Общими остаются очередь, месячная память, хранение и выгрузка.
- Ошибка одного потока больше не прерывает обработку остальных сайтов. Восстановление ограничено тремя попытками; после этого причина сохраняется в состоянии источника.
- Для облачных источников публикуются текущий этап, время прогресса и число восстановлений.
- Промежуточные результаты и порции найденных ссылок сохраняются в outbox; уже обработанные страницы остаются в PostgreSQL.
- Ошибки отдельных перенаправлений не считаются серией сетевых сбоев всего источника. HTTP 401/403/429, CAPTCHA и непроверенный robots.txt по-прежнему останавливают источник.

В старой реализации исключение из одного `Future` могло завершить общий цикл
сборщика, оставив состояния «Сбор идёт». Точный текст исключения прежнего облачного
процесса не сохранился; установлен дефект обработки ошибок, но не доказана конкретная
причина каждого прежнего перезапуска.

## Живой запуск и выгрузка

После первой части исправлений, на 30.09.2026 04:59 UTC, в запуске №11 сохранены
1 696 новых позиций BESKONTA, 140 СЕНСОР и 27 ТЕКО. Затем выявлена и исправлена
описанная выше ошибка регистра заголовка перенаправления BESKONTA.
Полный каталог на момент аудита ещё собирается. Количество исполнений BESKONTA
может превышать количество обработанных карточек.

Проверена фактическая цепочка `Library.with_specifications → export_tables →
xlsx_bytes/csv_bytes` на трёх наблюдениях из рабочей базы:

- BESKONTA SOT-18V75-P84-NONC-NPN-6000-IP-ST-C1: 17 характеристик.
- СЕНСОР ДКЕ-С300-300Р-3123-СА.2: 24 характеристики.
- ТЕКО «Блок контроля частоты CF2-2R-RS485»: 24 характеристики.

В XLSX получены листы «Результаты» и «Характеристики», всего 65 строк свойств.
CSV содержит отдельные столбцы характеристик. Секреты подключения и HTML-дампы
в репозиторий не публикуются.

Локально: 104 теста, без ошибок, 11 проверок PostgreSQL пропущены при отсутствии
локальной тестовой БД. GitHub Actions дополнительно запускает проверки с отдельной
PostgreSQL; рабочая база не используется для тестовых записей.

Состояние «Уже собрано в месяце» означает успешную предыдущую проверку,
а не ошибку парсера. Для таких карточек повторная цена в этом месяце не создаётся.
