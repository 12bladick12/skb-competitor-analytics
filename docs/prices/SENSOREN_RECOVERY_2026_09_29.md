# Sensoren: зависание запуска №10 и восстановление

Проверка 29 сентября 2026 года. Дополнение к [аудиту способов доступа](SENSOREN_OPTIONS_2026_09_29.md). Цены в базе являются снимками на дату получения.

## Установленная причина

Запуск LANBAO остановился после 13 карточек. Снятый стек работающего процесса показал ожидание ответа PostgreSQL в `record_products → batch → psycopg.wait_select`. Поток heartbeat продолжал работать, поэтому интерфейс показывал подключённый сборщик. На сервере не было соответствующего выполняющегося запроса; последняя карточка уже была записана.

На локальном соединении воспроизведена зависимость от объёма переданных данных. Точная причина на уровне сети или промежуточного оборудования не установлена. Это наблюдение не доказывает неисправность сервиса Supabase в целом.

| Проверка | Наблюдение |
|---|---|
| Отдельное соединение, синтетические данные 4–8 КБ | Ответ получен |
| Передача или получение 16–32 КБ | Клиентский таймер прервал ожидание |
| Несколько небольших запросов в одном соединении | Первые ответы получены, затем ожидание зависло |
| Pooler 5432 и 6543 | Проблема воспроизведена на обоих портах |
| Simple/extended protocol, отдельные SQL-команды | Большой обмен продолжал зависать |
| Psycopg 3, psycopg2 и pg8000 | Смена драйвера проблему большого обмена не устранила |
| TLS 1.2 | Большой обмен продолжал зависать |
| Прямой адрес PostgreSQL проекта | Из этой среды подключиться не удалось |
| Данные по 2200 байт, отдельное TLS-соединение для каждой части | Пакет 32 КБ доставлен полностью |

Проверки передавали синтетический текст; секреты и cookies в протокол не включались. Альтернативные драйверы не добавлены в зависимости приложения.

## Что изменено

1. Ограничено ожидание ответа клиента PostgreSQL: до 45 секунд для обычного обращения, до 15 секунд для передачи части карточки. Серверные `statement_timeout` и `lock_timeout` сохранены. После неопределённого исхода записи соединение закрывается, состояние сверяется с постоянной очередью.
2. Для внешнего Sensoren в режиме `--fresh-connections` характеристики и цена передаются небольшими частями через отдельные TLS-соединения. После проверки целостности фиксированная серверная операция атомарно записывает карточку, характеристики, цену, месячную память и состояние страницы.
3. Передаваемый документ содержит только данные. Он не содержит исполняемых SQL-команд. Функции работают с правами существующего подключения (`SECURITY INVOKER`), находятся в служебной схеме и не доступны роли PUBLIC.
4. Проверяются действующий владелец сборщика, срок его heartbeat, отмена запуска, источник и выбранный производитель. Повтор применения одного пакета возвращает прежний результат без новой записи истории.
5. Перед сохранением карточка остаётся в локальном файле передачи. После обрыва сборщик повторяет сохранение с исходной датой и характеристиками. Подтверждённые карточки не загружаются заново. Удалять папку `data/sensoren_agent` во время восстановления нельзя.
6. Очередь ссылок передаётся небольшими пакетами. Состояние основного потока публикуется отдельно от heartbeat: загрузка страницы, разбор, поиск ссылок, сохранение, восстановление соединения. В интерфейсе видны текущий этап и число восстановлений; затянувшийся этап вызывает предупреждение.

Обычный сборщик остальных источников продолжает использовать существующий путь записи с добавленным ограничением ожидания клиента. Локальная папка передачи не заменяет постоянную базу истории.

## Доступ к Sensoren и отбор товаров

Работает штатный браузерный транспорт Playwright/Chromium и HTTP-клиент той же анонимной сессии. Каталог начинается со страниц выбранных брендов; затем обходятся опубликованные категории, пагинация и карты сайта. Производитель повторно проверяется в карточке. Неопознанные по URL товары могут быть просмотрены, но товары других производителей не записываются.

Паузы, robots.txt, ограничение частоты восстановления сессии и остановка при CAPTCHA/401/403/429 сохраняются. Новые прокси, подмена cookies, закрытые API и обход авторизации не добавлены. Ранее проверенные альтернативы описаны в отдельном аудите; для текущего зависания подтверждённая неисправность находится на этапе сохранения.

## Проверка результата

- До исправления: 13 сохранённых карточек, последняя проверка 08:32:40 UTC.
- После перезапуска внешнего агента в 09:37:54 UTC: 62 карточки к 09:45:11 и 85 карточек к 09:48:48 UTC; текущая очередь продолжена.
- В проверенной выборке все товары относятся к LANBAO; у первых 62 карточек сохранено 14–20 характеристик. Продолжилась обработка категорий и карт сайта. На этой точке наблюдения ошибок восстановления не было.
- Автоматические проверки покрывают обрыв до и после commit, повтор применения пакета, крупные UTF-8 документы, отмену, истёкшее право сборщика, посторонний бренд, неполный пакет, откат повреждённой записи, загрузку отдельного задания, отсутствие дублей в месяце и новую цену с сохранением истории следующего месяца.
- Интеграционные проверки выполняются в отдельной временной PostgreSQL-схеме. Рабочие таблицы истории ими не очищаются.

Эти данные подтверждают возобновление сбора и прохождение проверок восстановления. Завершение полного каталога всех шести производителей этим промежуточным наблюдением не подтверждается. Текущий запуск продолжает работу; итоговое покрытие нужно смотреть по его завершению.

## Эксплуатация

Внешний агент запускается с `--enable --fresh-connections --transport browser`; используются существующие локальные secrets. Компьютер с агентом должен работать и иметь сеть. При переносе на постоянно работающий сервер используются те же очередь и база. Версия агента в lease начинается с `sensoren-monthly1-io2-`, облачного сборщика — с `router2-monthly1-io2-`.

После обновления GitHub уже запущенный старый облачный процесс может потребовать Reboot app в панели владельца Streamlit. Перезапуск сохраняет очередь и историю. Новый запуск каталога ради этого создавать не требуется.

## Документация, использованная при проверке

- [Psycopg: пул подключений](https://www.psycopg.org/psycopg3/docs/api/pool.html): время получения соединения из пула и время выполнения SQL — разные ограничения.
- [Psycopg: прерывание операций](https://www.psycopg.org/psycopg3/docs/advanced/async.html): при прерывании необходимо учитывать неопределённый исход операции.
- [PostgreSQL: параметры libpq](https://www.postgresql.org/docs/16/libpq-connect.html): connect_timeout и параметры сетевого соединения.
- [Supabase: подключение к PostgreSQL](https://supabase.com/docs/guides/database/connecting-to-postgres): прямое подключение, session pooler и transaction pooler.
- [Playwright: APIRequestContext](https://playwright.dev/python/docs/api/class-apirequestcontext): HTTP-клиент контекста использует его cookies.
