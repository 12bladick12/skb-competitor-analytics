# Постоянная база и паспорта

База хранит товары, историю цен и выбранные соответствия постоянно. Повторный сбор не заменяет историю новым снимком и не создаёт цену из месячной памяти.

| Действие | Периодичность |
|---|---|
| Поиск ссылок на новые карточки | Каждый запуск |
| Полная обработка новой карточки | Сразу после обнаружения |
| Цены, характеристики и исполнения известных карточек | Один раз в календарный месяц UTC |
| Проверка прежнего PDF | Ежемесячно; новая ссылка — после её обнаружения |
| Заполнение геометрии | Сотрудником по текущему паспорту |
| Проверка отсутствующих карточек | После полного успешного обхода навигации выбранного источника |

Новое исполнение внутри старой карточки обнаруживается при месячном обновлении. Отрицательный результат поиска паспорта сохраняется до следующего месячного задания или ручной проверки.

## Источники технических документов

| Источник | Правило |
|---|---|
| МЕГА-К | Поле «Технический паспорт», относительный URL с учётом `<base href>` |
| ТЕКО | Раздел документации; в том числе ссылка `file_download.php?id=…` без расширения |
| СЕНСОР | Документы товара; общий паспорт серии имеет отдельные связи с исполнениями |
| BESKONTA | Документы карточки и официальный раздел информации; отсутствие файла фиксируется |
| Sensoren | Раздел документов; дополнительный поиск на официальном сайте соответствующего производителя |

Дополнительные домены: Autonics — autonics.com; Balluff — balluff.com, assets.balluff.com, publications.balluff.com; Pepperl+Fuchs — pepperl-fuchs.com, files.pepperl-fuchs.com; ifm — ifm.com, media.ifm.com; LANBAO — cnlanbaosensor.com, lanbaosensor.com; SICK — sick.com, cdn.sick.com. Файловые адреса берутся из опубликованных ссылок и проверенного реестра аудита. Цена всегда остаётся связанной с первоначальным источником.

Разрешены паспорта, datasheet и технические описания конкретной модели/серии. Сертификаты, прайс-листы, CAD, рекламные материалы и отдельные изображения исключаются. Надпись «PDF» не доказывает формат: проверяется ответ и открытие PDF. Запрет robots.txt сохраняется как причина отказа и не обходится.

Документ серии не подтверждает размеры исполнения автоматически. Полное обозначение в техническом документе подтверждает связь документа с моделью; конкретный чертёж, размер и его применимость сотрудник проверяет отдельно. Ограниченный дополнительный поиск не является доказательством отсутствия документов на всём сайте.

## История и отсутствие товара

Сбой сети, 403/429, пустой результат парсера и незавершённый обход не означают удаление. Пропавшая ссылка вызывает адресную проверку. Для архивирования нужны две независимые проверки 404/410 с интервалом не менее суток. Отсутствующее исполнение BESKONTA проверяется отдельно по полностью прочитанному составу вариантов. Пустая или повреждённая таблица таким основанием не является.

Доступная карточка сохраняется активной, даже если ссылка исчезла из перечня. Перенаправление с подтверждённым полным обозначением сохраняет идентификатор и историю. Сомнительное совпадение обозначений по разным URL не объединяется автоматически. Архивирование сохраняет цены, паспорта и сравнения. Наличие и снятие с производства — отдельные состояния.

## Просмотр и ручная проверка

Файлы хранятся по SHA-256 в закрытом Supabase Storage. Просмотр использует временные ссылки на 10 минут. Внутренние корпоративные паспорта не входят в автоматическую загрузку и не публикуются вместе с кодом.

Автоматическое распознавание изображений удалено. PDF проверяется на корректность и читается только его существующий текстовый слой. Для просмотра страница отображается как изображение; её содержание не анализируется моделью. Если извлекаемого текста нет, тип документа и применимость нельзя подтвердить автоматически.

Геометрию сотрудник заполняет вручную по паспорту. Проверка введённых значений отклоняет неизвестные поля, неверные страницы, области вне чертежа, нечисловые размеры и размеры без единиц/базы измерения.

Каждое поле имеет страницу, область чертежа, основание и применимое исполнение. Длина чувствительного элемента, выступающей части и корпуса хранятся раздельно. Размеры по пикселям не вычисляются. Подтверждение сотрудника привязано к конкретному товару и отпечатку документа; новая редакция не получает подтверждение старой автоматически.

В подбор передаются только подтверждённые поля текущей редакции. Стандартное и погружное исполнения разделяются. Подтверждённое противоречие не заменяет молча сведения карточки. Длина чувствительного элемента обязательна; погружная длина — выше важных характеристик, без автоматически введённого допуска. Для ёмкостных изделий эти поля подготовлены для отдельного алгоритма подбора; индуктивный алгоритм не применяется к ёмкостным автоматически.

Получение паспортов имеет независимую очередь, аренду задания и повтор после временной ошибки. В разделе «Паспорта» доступны причины отказов, просмотр, ручное прикрепление и подтверждение введённых сотрудником полей. Даты цены, карточки и паспорта показываются отдельно.

## Настройка обработчиков

Секреты хранятся только в закрытом `.streamlit/secrets.toml` и Secrets приложения:

```toml
[passports]
url = "https://PROJECT.supabase.co"
service_key = "SECRET_STORAGE_KEY"
bucket = "competitor-passports"
```

Раздел `[database]` использует существующее подключение. Ключ Storage не включается в GitHub и не передаётся браузеру. Приложение проверяет, что bucket закрытый; недоступное хранилище не останавливает сбор цен.

```powershell
python -m pip install -r requirements.txt
python -m price_monitor.passport_worker --queue download --settings .streamlit/secrets.toml
```

Облачное приложение запускает очередь загрузки при наличии настроек Storage. При необходимости её можно запустить отдельным процессом с `--queue download`. Для ограниченного испытания доступны `--once`, `--limit N` и локальные `--db PATH --offline-files DIRECTORY`. Локальное испытание не загружает файлы в Supabase.

Автоматические задания анализа изображений больше не создаются. Просмотр действительного паспорта остаётся основанием подтверждения геометрии.
