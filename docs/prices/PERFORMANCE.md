# Диагностика скорости 29 сентября 2026

## Что обнаружено

- В запуске №6 карты сайта и разделы имели безусловный приоритет над товарами.
  К моменту диагностики ожидали обработки 42 652 карточки четырёх источников,
  при этом сохранённых позиций этого запуска ещё не было. Обход разделов мог
  продолжаться долго после обнаружения самих товаров.
- Каждая операция каталогов, включая чтение прогресса, создавала новое соединение
  и получала общую блокировку записи. Это замедляло как сбор, так и интерфейс.
- Прямой ответ Supabase на порту 5432: `EMAXCONNSESSION`, лимит 15 клиентов в session mode.
  Диагностика готового соединения давала примерно 0,09–0,68 с на запрос, первое
  соединение — 1,6 с. Это замеры с компьютера разработчика, не из Community Cloud.
- Чтение через transaction pooler того же проекта на 6543 прошло: подключение 0,70 с,
  запрос текущего запуска 0,12 с. Это не прогноз времени полного сбора.
- Среди ошибок очереди есть запрещённые robots.txt ссылки, 404 карты BESKONTA,
  пустые перенаправления и превышение лимита размера/времени карт Sensoren.
  Они остаются видимыми; ограничения источников не отменяются.

## Изменения

- Сначала обрабатываются известные карточки; каждая двадцатая итерация отдаётся
  обнаружению новых ссылок. Если карточек пока нет, сначала открывается каталог.
- Добавлен индекс для выбора следующей страницы. Данные и уже найденная очередь сохраняются.
- Пакет из 250 ссылок вставляется одним SQL-оператором.
- Каталоги и внешний агент используют общий в пределах процесса пул соединений.
  Чтения выполняются без общей блокировки записи; изменения остаются транзакционными.
- Подключения к `*.pooler.supabase.com:5432` направляются на transaction endpoint того же
  хоста, порт 6543. Пароль, проект и схема те же. Другие PostgreSQL-хосты не перенаправляются.
  Prepared statements отключены, настройки и блокировки действуют внутри транзакции.
- В прогрессе отдельно видны обработанные карточки, оставшиеся разделы и последнее время обработки.

Официальное описание режимов: https://supabase.com/docs/guides/database/connecting-to-postgres .

## Применение

Обновите `main` и перезапустите основной процесс Streamlit (**Reboot app**). Если отдельное
приложение цен ещё работает, удалите его из Streamlit после проверки основного: оба используют
общую очередь, и старый процесс может удерживать её. Supabase и внешний Sensoren-агент удалять не нужно.
Внешний агент должен быть перезапущен с теми же обновлёнными модулями. Запуск №6 и его очередь
продолжатся, создававшиеся задания не нужно загружать заново. При аварийном завершении прежнего
процесса освобождение его блокировки занимает до 120 секунд.

## Реалистичный объём

Для одного сайта запросы идут последовательно с паузой минимум 2 секунды после ответа,
либо больше согласно robots.txt. Только 28 654 карточки ТЕКО требуют не менее примерно
16 часов пауз, плюс сеть, обработка и служебные страницы. Источники обрабатываются параллельно.
Паузы хостинга и недоступность источника увеличивают календарное время.

Для ежедневной работы используйте список интересующих моделей или Excel-выборку.
Google Sheets подходит для наших цен, выбора моделей и согласования соответствий;
история, характеристики и очередь сбора остаются в PostgreSQL. Перенос хранения в
таблицу сам по себе не ускоряет обращения к сайтам. Sheets API имеет отдельные квоты:
https://developers.google.com/workspace/sheets/api/limits .
